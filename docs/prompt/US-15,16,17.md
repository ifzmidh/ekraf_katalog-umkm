# 2. US-15: URUTKAN PRODUK

Sebagai pengunjung, saya ingin mengurutkan produk, supaya cepat menemukan yang murah atau yang terbaru.

### Acceptance Criteria

1. Ada pilihan urutan:
   - Termurah.
   - Termahal.
   - Terbaru.

2. Urutan diterapkan saat mengambil data (query), bukan hanya di tampilan.

### Implementasi

Tambahkan kontrol sorting pada halaman katalog `/`.

Pilihan sorting:

| Label    | Parameter URL     | Query Supabase    |
| -------- | ----------------- | ----------------- |
| Terbaru  | `sort=latest`     | `created_at DESC` |
| Termurah | `sort=price_asc`  | `harga ASC`       |
| Termahal | `sort=price_desc` | `harga DESC`      |

Ketentuan:

- Default sorting adalah terbaru.
- Gunakan parameter URL `sort`.
- Sorting harus dilakukan di query Supabase pada server.
- Jangan melakukan sorting menggunakan JavaScript di browser.
- Jika parameter sorting tidak valid, gunakan default terbaru.
- Pertahankan filter pencarian dan kategori jika sudah tersedia.
- Perubahan sorting tidak boleh menghilangkan parameter URL lainnya yang masih relevan.

Gunakan shadcn Select untuk kontrol sorting.

# 3. US-16: PAGINASI PRODUK

Sebagai pengunjung, saya ingin daftar produk tidak terlalu panjang, supaya halaman cepat dibuka.

### Acceptance Criteria

1. Daftar produk dipecah per halaman atau ada tombol "Muat lebih banyak". (4 poin)
2. Pembatasan jumlah dilakukan di query database, bukan hanya disembunyikan. (3 poin)
3. Navigasi antar halaman berfungsi dan jumlah halaman benar. (3 poin)

### Implementasi

Gunakan pagination berbasis URL.

Parameter:

- `page`: nomor halaman.
- `limit`: jumlah produk per halaman, jika diperlukan.

Default:

- Halaman pertama.
- 12 produk per halaman.

Contoh URL:

`/?page=1`
`/?page=2`
`/?page=3&sort=price_asc`

Ketentuan teknis:

1. Gunakan Supabase `.range(from, to)` untuk membatasi data di database.
2. Gunakan `count: 'exact'` ketika mengambil data agar total produk diketahui.
3. Hitung total halaman berdasarkan total data dan page size.
4. Jangan mengambil seluruh produk kemudian memotong array di browser.
5. Validasi nomor halaman agar tidak negatif atau tidak valid.
6. Jika halaman melebihi jumlah halaman yang tersedia, tangani dengan jelas, misalnya arahkan ke halaman terakhir atau tampilkan empty state yang sesuai.
7. Pagination harus mempertahankan sorting, pencarian, dan filter kategori.
8. Ketika sorting atau filter berubah, reset halaman ke halaman pertama.

### UI Pagination

Gunakan komponen shadcn:

- Pagination.
- PaginationContent.
- PaginationItem.
- PaginationLink.
- PaginationPrevious.
- PaginationNext.
- PaginationEllipsis jika diperlukan.

Tampilkan informasi:

- Total produk.
- Halaman saat ini.
- Total halaman.

Pastikan tampilan pagination responsive dan nyaman digunakan di HP.

# 4. US-17: PRODUK TERKAIT

Sebagai pengunjung, saya ingin melihat produk lain yang mirip, supaya saya punya pilihan lain.

### Acceptance Criteria

1. Halaman detail menampilkan beberapa produk lain dari kategori yang sama. (3 poin)
2. Produk yang sedang dibuka tidak ikut ditampilkan, dan data diambil dari database. (2 poin)

### Implementasi

Pada halaman detail:

`/produk/[id]`

Tambahkan section:

"Produk Terkait"

Tampilkan beberapa produk yang memiliki kategori sama dengan produk aktif.

Ketentuan query:

1. Ambil kategori dari produk yang sedang dibuka.
2. Ambil produk lain dengan kategori yang sama.
3. Kecualikan ID produk aktif menggunakan `.neq('id', currentProduct.id)`.
4. Ambil data langsung dari Supabase di server.
5. Batasi hasil maksimal 4 produk.
6. Gunakan urutan terbaru berdasarkan `created_at DESC`.
7. Jika tidak ada produk terkait, sembunyikan section atau tampilkan empty state yang sesuai.
8. Jika kategori produk kosong, jangan menjalankan query kategori yang tidak diperlukan.

### UI

Gunakan ProductCard yang sama dengan halaman katalog.

Tampilan:

- Heading "Produk Terkait".
- Grid 2 kolom di mobile.
- Grid 4 kolom di desktop.
- Foto produk.
- Kategori.
- Nama produk.
- Harga rupiah.
- Link menuju detail produk terkait.

Jangan membuat komponen kartu produk baru jika ProductCard yang sudah ada dapat digunakan kembali.

# 5. INTEGRASI ANTARFITUR

Ketiga fitur harus bekerja bersama.

Contoh:

`/?page=2&sort=price_asc`

Artinya:

- Pengunjung sedang membuka halaman kedua.
- Produk diurutkan dari harga termurah.
- Jumlah produk tetap dibatasi sesuai pagination.

Jika nantinya terdapat pencarian dan filter kategori, semua parameter tersebut harus tetap dipertahankan saat berpindah halaman atau mengganti sorting.

Ketentuan:

- Search tidak boleh mereset sorting.
- Sorting tidak boleh menghilangkan kategori.
- Pagination tidak boleh menghilangkan search.
- Mengubah sorting atau filter harus kembali ke halaman pertama.
- Navigasi harus menggunakan URL yang valid dan dapat dibagikan.
